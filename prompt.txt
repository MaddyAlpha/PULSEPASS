#### **Pillar 2: The 3-Phase Security & Gate Architecture**

##### **Phase 1: Secure Digital Claiming (Database-less OCR Approach)**
* **The UI:** Build a mobile-first claim screen where a user enters their Roll Number.
* **Camera & Blur Detection:** Use the browser's `MediaStream` API to open the camera with continuous autofocus. Implement a client-side JavaScript Laplacian filter to analyze frame sharpness. Keep the "Capture" button disabled until the card frame is crisp and clear.
* **Client-Side OCR:** Integrate `Tesseract.js`. When captured, scan the ID card image locally for target university/department keywords (e.g., `"Krishi Vishvavidyalaya"` or `"Life Science"`).
  * **Success:** Instantly issue a dynamic, time-based (TOTP) QR code pass.
  * **Failure:** Clear the frame, inform the user, and prompt them to retry.
* **Manual Fallback:** If OCR fails 3 consecutive times, reveal a "Submit for Manual Review" option that pushes the image to an admin approval queue with a `Pending` status.

##### **Phase 2: Real-Time Gate Security Pipeline**
* **Real-time Sync Engine:** Utilize Supabase Realtime subscriptions so state changes sync across gate devices in milliseconds.
* **Station 2: The Scanner UI (`/scanner/[eventId]`):** Build a rapid camera-based QR scanner. Scanning a dynamic ticket updates its status to `Pending Verification`. Provide full-screen visual and haptic feedback (bright green flash for valid; bright red for invalid/already scanned).
* **Station 3: The Verifier UI (`/verifier/[eventId]`):** Build a live-updating dashboard displaying an auto-scrolling grid of selfies/IDs for tickets that just passed Station 2. Provide a prominent "Admit" button that permanently burns the ticket (`checked_in = true`).

##### **Phase 3: VIP & Admin Governance**
* Build a protected route within the Org Dashboard to manually issue VIP passes that bypass the OCR verification flow.
* Include a review queue interface for admins to visually inspect and bulk approve/reject "Pending" fallback submissions from Phase 1.
