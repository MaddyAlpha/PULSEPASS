# PulsePass: Comprehensive Architecture & User Flow Blueprint

## 1. Core Architecture & Multi-Tenant Routing
PulsePass operates on a strictly structured multi-tenant system with unified authentication.

*   **Unified Authentication:** All users log in through a single `/login` entry point.
*   **The Role Router:** Upon login, Supabase checks the user's `profiles.role` and redirects them automatically.
*   **Hybrid Routing Strategy:** 
*   Public-facing event discovery utilizes URL-based tenant scoping (e.g., `/u/cskhpkv/events`).
*   Private management dashboards utilize invisible silent tokens locked via Row Level Security (e.g., `/org/dashboard`).

## 2. User Roles & The Hierarchy Engine
The platform relies on a strict top-down permission structure.

*   **Super Admin:** The platform owner who provisions parent institutions (Universities).
*   **University Admin:** The top-level institution manager (e.g., Vice Chancellor or IT Lead).
*   **College Admin:** Department-level managers (e.g., Head of the College of Agriculture).
*   **Organiser:** The CEO of a specific event or fest.
*   **Committee Head:** Appointed by the Organiser to manage specific domains (Finance, Logistics).
*   **Student:** The end-user who browses events and claims passes.
*   **CR Verifier:** A Class Representative assigned to verify ID selfies strictly for their own batch.
*   **Scanner/Verifier Volunteer:** Day-of-event staff handling physical gate check-ins.

## 3. Account Creation & Security Validations
The public registration is strictly designed for students to prevent unauthorized org accounts.

*   **The Signup Form:** Contains strictly Student fields (Name, Email, Password, University Dropdown, Roll Number).
*   **Regex Pattern Enforcement:** When a student selects their university (e.g., CSKHPKV), the Roll Number field dynamically applies the exact Regex format set by the University Admin.
*   **OCR Synergy:** This strict regex pattern is later fed to the Phase 1 OCR engine to guarantee near-perfect reading of physical ID cards.

## 4. The Two-Tier Organiser Approval System (Double Lock)
Students cannot simply sign up as Organisers. Access requires a two-step validation.

*   **Step 1 (The Code):** College Admins generate a specific invite code bounded to their department.
*   **Step 2 (The Application):** A student enters this code in their dashboard. The app changes their status to `Pending Final Approval`.
*   **Step 3 (The Final Gate):** The University Admin reviews the pending queue on their global dashboard and clicks `Approve`, officially elevating the user to Organiser.

## 5. Event Creation & Committee Delegation
Organisers have complete control over event setup and team delegation.

*   **Event Setup Schema:** Organisers define the Event Name, Venue, Date, Banner Image, Capacity Limits, and strict Ticketing Windows.
*   **Committee Creation:** Organisers create teams based on Presets (Financial, Cultural, Logistics, Discipline).
*   **Head Appointment:** Organisers input a student's Roll Number to instantly appoint them as a Committee Head.
*   **Member Joining:** Regular students join committees by entering a dynamic 4-digit code generated by the Committee Head.

## 6. Smart CR Verification Routing (Pre-Event)
To prevent manual review bottlenecks, ID selfie verification is decentralized.

*   **University Master List:** The University Admin defines official batch scopes (e.g., `2026-LS` for Life Sciences).
*   **CR Assignment:** The Organiser appoints a CR and selects their batch scope from the university's locked dropdown menu.
*   **Smart Routing:** When a student with Roll Number `2026-LS-042` claims a pass, their ID selfie bypasses the global queue and routes directly to the dashboard of the `2026-LS` CR for approval.

## 7. The Ticketing & Gate Scanning Pipeline (Day-Of Execution)
The anti-fraud engine powering the physical entry at the venue.

*   **Dynamic QRs:** Passes generate a time-rotating JWT QR code that refreshes every 15 seconds, making screenshots completely invalid.
*   **Station 1 (The Scanner):** The Scanner Volunteer uses their device to scan the QR. The UI features browser haptic feedback and audio chimes.
*   **The Soft Lock:** Scanning instantly places a 60-second lock on the ticket in the database to prevent duplicate scans from other volunteers.
*   **Station 2 (The Verifier):** Using Supabase Realtime (WebSockets), the student's pre-verified ID selfie instantly pops up on the Verifier's screen with zero page refreshing required. The Verifier compares the live face to the screen and clicks `Admit`.

## 8. Committee Operations Tools
Committee Heads are provided with specific database tools to manage their departments.

*   **Financial Ledger:** A shared checkbook recording `INCOME` and `EXPENSE`. It logs the amount, vendor name, receipts (URLs), and the specific student who logged the entry.
*   **Logistics Tracker:** An inventory manager tracking items (e.g., Stage Speakers), vendor contacts, and the procurement status (`PENDING`, `PROCURED`, `RETURNED`).

## 9. The Standard Student Dashboard Modules
The daily hub for the general student body.

*   **My Passes (Digital Wallet):** Displays active Dynamic QRs and pending manual review statuses.
*   **Event Feed:** A scrolling list of upcoming university fests with "Claim Pass" and "Apply to Volunteer" (in-context) buttons.
*   **My Committees:** Displays joined groups and the 4-digit join code input field.
*   **Settings & Identity:** The profile vault for managing Roll Numbers, Base ID uploads, and requesting Organiser access.
